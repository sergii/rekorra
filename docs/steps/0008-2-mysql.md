# Step 0008.2 - Real MySQL 8.4 host compatibility

Status: CI pending. MySQL support is not claimed until the live GitHub Actions job passes.

## Goal

Verify the entire Rekorra test-host integration against real MySQL 8.4, not only SQLite or PostgreSQL: migrations, tenant-isolated CRUD, CSRF and field policy checks, PaperTrail JSON, Access Audit, typed forms and enums, bounded association lookup, Sidekiq/Solid Queue, and 50,000-row offset/keyset pagination.

## Approach

- Dedicated MySQL 8.4 service and Rails 8.1 / Ruby 3.4 integration job with Redis.
- Set REKORRA_TEST_DATABASE_URL to a MySQL URL and assert the primary ActiveRecord adapter is Mysql2; leave Solid Queue on SQLite.
- Install mysql2 only in the test host. Never make it a Rekorra gem runtime dependency.
- Make SQL instrumentation recognize backtick-quoted identifiers; do not weaken limits on SQL count, cursor validation or tenant scoping.

## Acceptance

- [ ] Real MySQL 8.4 service boots, migrations succeed, and Mysql2 is verified as the primary adapter
- [ ] Entire integration suite passes, including scope and forged-field rejection
- [ ] 50,000-user tests enforce SQL query bounds and offset/keyset behavior
- [ ] PaperTrail JSON, audit transactions, foreign keys and typed forms pass
- [ ] SQLite Rails/Ruby matrix, PostgreSQL, browser acceptance and installed gem jobs stay green
- [ ] Post-merge CI green

## Limits

Passing this integration gate will not prove production MySQL EXPLAIN plans, query latency, load/concurrency, collation behavior across languages or independent database transaction atomicity. No Rails 7, Sprockets-only, Turbo/Stimulus, worker E2E, Safari or screen-reader guarantee.
